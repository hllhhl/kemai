# 知页之外，还值得加什么

> 2026-11-04。判断标准只有三条：
> ① 学生真的会用到（不是"看起来高级"）；② 能在这套架构里落地（本地、无 ffmpeg、≤1GB）；
> ③ 知页原版没有。达不到三条的不列。

## 二、按场景列：值得加的 8 个

### 场景 A：期末只剩一周，72 讲看不完

#### 1. 整门课批量处理 ★★★★★

**问题**：现在一讲一讲点。72 讲要点完 72 次。

**怎么做**：复用知页的 `Job` 表做队列；每讲一条 job（导字幕 → 出要点）；断点续跑；
**先跑一个「成本预估」**：按每讲约 X 千 token 算出总花费，让用户确认后再启动。

**代价**：需要一个成本上限与中断恢复。不做上限就是给用户挖坑。

#### 2. 时间预算排程 ★★★★★

**问题**：知道有很多要学，但不知道今天该学哪几讲。

**怎么做**：**不需要模型**。输入"距离考试 5 天、每天 3 小时"，输出今天的顺序：

```
priority = 考频 × 0.4 + (1 - 掌握度) × 0.4 + 先修已过 × 0.2
每日容量 = 可用分钟 / 每讲平均时长
```

直接产出「今天：P12 → P13 → P15」，点一下就开那一讲。

**代价**：几乎为零，纯计算。这是投入产出比最高的一项。

### 场景 B：看完记不住

#### 3. 主动回忆卡（挖空 + 复述检查） ★★★★

**问题**：读笔记是被动学习，合上书就忘。

**怎么做**：
- **挖空**：从要点里抽术语做 cloze（`栈是〔后进先出〕的线性表`），零模型成本；
- **复述检查**：让用户口述或手打一段，用已有的 embedding 与要点做覆盖率比对，
  标出「漏了哪几条」。这比判对错有用得多。

**代价**：复述检查需要 embedder（已有），不需要额外模型。

#### 4. 间隔重复接到视频片段 ★★★

**问题**：知页有 FSRS，但只挂在知识点上，视频片段没入链。

**怎么做**：要点生成时给每条打 `kp_id`（能挂上就挂），到期复习时直接跳到
`bilibili.com/video/BVxxx?t=204` 那一秒。

**代价**：需要先解决「要点 → 知识点」的对齐（目前字幕不进知识点树）。

### 场景 C：做题

#### 5. 从视频/课件自动出题 + 变式 ★★★★

**问题**：知页的 practice 基于上传试卷；没有试卷就没有题。

**怎么做**：拿 digest 的要点 + 对应课件页当上下文，走现有的 `practice_generation`，
要求「同一知识点出 1 道原样 + 2 道变式（换数字/换问法/反向问）」。

**代价**：纯模型调用。质量取决于要点质量。

#### 6. 错因归类 + 同类题 ★★★

**问题**：现在只有对错，不知道自己错在哪一类。

**怎么做**：判错后弹一次单选（概念不清 / 计算错 / 审题错 / 根本没学过），
存进 `memory`；再按错因推荐同知识点的其他题。

**代价**：一次点击的交互成本。归类后能显著改善「推什么题」。

### 场景 D：跨课程

#### 7. 跨课先修图 ★★★

**问题**：数字集成电路学不动，可能是模电没学好——但现在五门课各自为战。

**怎么做**：图谱的 `prereq` 边允许跨课程连接（同名词典 + 课程名做前缀）。
先做**只读视图**：这门课依赖哪些别的课的知识点。

**代价**：跨课对齐容易误连，先只展示不自动干预。

### 场景 E：用起来顺手

#### 8. 引用直接跳视频那一秒 ★★★★★

**问题**：引用写着「第 3 讲 03:24–04:10」，但点不动。

**怎么做**：locator 里已有 `bvid/part/from`，前端拼
`https://www.bilibili.com/video/{bvid}?p={part}&t={from}` 即可。

**代价**：几乎为零，体验提升最直接。**这个应该立刻做。**

## 三、不建议做的（以及为什么）

| 想法 | 为什么不做 |
|---|---|
| 内置 whisper 本地转写 | 模型 100MB+，CPU 上一小时音频要跑十几分钟；字幕和 OCR 已经覆盖大部分场景 |
| 云端账号 + 多端同步 | 违背「本机单用户、资料不出门」的定位；真要同步，导出文件比建账号便宜 |
| 手机 App | 一套 UI 两套维护，收益远小于把 Web 端做好 |
| 自动挂机刷课 / 自动答题 | 违反平台规则，也有学术诚信问题，不碰 |
| 自建向量模型 / 换 embedding | 知页的 Granite 311M 已经够用，换模型要重建全部索引，得不偿失 |
| 全自动"一键学会一门课" | 承诺不了。能承诺的是「缩短找资料和整理的时间」，不是「替你学会」 |

---

## 四、如果只做三个

按「投入产出比 × 学生痛感」排：

1. **引用跳视频秒数**（半天，体验立刻不同）
2. **时间预算排程**（两天，不需要模型，直击"不知道学什么"）
3. **整门课批量处理**（三天，带成本预估，把 72 讲从 72 次点击变成 1 次）

这三个做完，产品从「能查」变成「能安排」。后面的出题、挖空、跨课依赖它们产出的数据。

---

## 五、一条判断原则

以后每加一个功能，先问一句：

> **它是在缩短「找资料 + 整理」的时间，还是在假装替学生学会？**

前者可以做，后者不做。这条线决定了这个产品是工具还是安慰剂。
